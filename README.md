# OI EXCHANGE

面向双方协作的**独立 App 交互原型**。当前版本是单文件、本地运行的演示，不是已上线的多人协作服务。代码入口为 [`index.html`](index.html)，不依赖 Oxford Bot。

## 本地运行

需要现代浏览器；推荐通过本地静态服务器打开，避免不同浏览器对 `file://` 页面的存储行为不一致：

```bash
python3 -m http.server 8080
```

然后访问 `http://localhost:8080/`。命令应在仓库根目录运行；如本机没有 Python 3，可用任意本地静态文件服务器。无需安装项目依赖。

## 当前可演示的流程

1. 创建项目，填写甲乙双方、共同目标、允许共享范围和交付验收标准；也可载入**虚构**示例。
2. 分别切换甲方、乙方角色，模拟确认当前约定版本。双方都确认前，不允许提出新交接。
3. 填写交接任务，人工勾选已核对共享范围，生成固定模板草案并提交本地模拟审批。
4. 切换到接收方，核对声明并填写处理理由，然后模拟批准或拒绝；理由会留在交接详情及操作记录。
5. 修改项目约定后，版本递增、双方确认重置、旧版本尚未处理的请求作废；按新版本重新确认后可继续提出交接。
6. 可删除当前浏览器中的项目及其演示记录。

## 手动验收清单

- [ ] 新建项目后，未获双方模拟确认时无法提交交接。
- [ ] 仅甲方确认仍无法提交；切换到乙方确认后才可提交。
- [ ] 提交交接时未勾选共享范围核对声明，表单不会提交。
- [ ] 切换到发起方时无法处理自己的待审批请求；切换到接收方时，缺少核对勾选或处理理由则不能批准或拒绝。
- [ ] 成功处理后，理由显示在交接详情和本地操作记录中。
- [ ] 对仍待审批的交接修改约定，会使该请求作废；双方必须重新确认新版本。
- [ ] 刷新同一浏览器的同一站点后，演示项目仍在；删除项目后刷新不再出现。

以上是**人工检查步骤**，不是自动化测试已通过的声明。

## 必须了解的边界

- 任意人都可在同一浏览器切换甲乙角色；“确认”和“审批”**不是真实身份验证、签署或授权**。
- “AI 草案”使用固定模板，不会调用模型、执行任务或向对方发送消息。
- 数据保存在当前浏览器的 `localStorage`；没有账号、后端数据库、跨设备同步或可信审计。清理浏览器数据可能导致记录丢失。
- 不要填写真实合同、个人数据、密钥或其他敏感资料。这里的“已核对范围”只是人工勾选，系统不会自动验证内容是否在共享范围内。
- 提交到 GitHub 只代表保存了代码；不代表网站已部署或服务已上线。

## 从原型走向正式版

在允许真实双方协作前，还需要单独设计和实现：组织与成员身份、服务端项目权限与邀请、服务端版本化约定和审批状态、可信的事件记录、共享内容的访问控制及保留/删除策略。真实 AI 交接应在这些边界建立后，再接入受控工具和人工审批。当前仓库**尚未实现**这些正式版能力。
